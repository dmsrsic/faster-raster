# Handle Registry privacy and governance

The registry is an opt-in public record. Version 1 contains only a chosen lowercase handle, a random member ID, acceptance date, status, signing-key control metadata, and up to five fixed interests. It contains no contact details, biographies, coordinates, project paths, credentials, browser identifiers, or analytics joins.

A handle is not a user count, account, credential, entitlement, endorsement, or proof that one human exists. Maintainers approve create, rename, update, retirement, suspension, and removal actions using objective reason codes. There is no inactivity retirement.

Git history, forks, mirrors, and archives may retain records after current-site removal. Key loss cannot be recovered as identity; a replacement receives a new member ID.

Public request intake is enabled through a GitHub Issue Form. GitHub displays the issue author's public username and retains issue history. FasterRaster does not automatically copy that username into the generated Handle Registry index merely because a request exists, and a request is not an active member record. Automatic activation, local key generation, signed-claim verification, account recovery, and identity verification remain disabled. No analytics join connects requests or handles to clone or view traffic.
